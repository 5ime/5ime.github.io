写在前面

最近领导要求把摄像头的实时串流接进正在开发的大屏。还好设备自带 Web 预览页，登录之后就能看到可见光和热成像两路画面

既然官方页面自己就能实时预览，那就先按 F12 瞅一眼，看看画面是怎么出来的

页面结构

Elements 里没有 <video>，画面是直接画在 canvas 上的。canvas0 底下还压着一层同样大小的画布，一层画视频，一层画叠加

Network 里两条 WebSocket 一直挂着，顺着调用栈翻打包后的 app.*.js，能看到这么一段

var r = window.sessionStorage.getItem("token");
var l = "/v1/webstream/data?chn=0&streamtype=0&x-token=" + r;
var n = "/v1/webstream/data?chn=1&streamtype=0&x-token=" + r;

this.options = [{
  root: "videoApp",
  subtype: 1,
  wsURL: "ws://" + host + ":" + port + l,
  rtspURL: "rtsp://" + host + ":9554/live?channel=0&subtype=",
  username: "admin",
  password: "admin123",
  decodeMode: "canvas"
}, {
  root: "videoApp",
  subtype: 1,
  wsURL: "ws://" + host + ":" + port + n,
  rtspURL: "rtsp://" + host + ":9554/live?channel=1&subtype=",
  username: "admin",
  password: "admin123",
  decodeMode: "canvas"
}]

两路就这么对上了，chn=0 / channel=0 是可见光，1 是热成像

rtspURL 里的 9554 是官方包内部给 WebSocket 通道用的 RTSP URI 端口

博主一开始以为设备对外的 RTSP 也是这个端口，ffprobe 连了半天没反应，扫了下端口才发现对外开的是 554

设备码流

首页 HTML 里串着一堆 loadJS('static/h5player/...')，上面那两条 WS 就归它管。码流收下来，WASM 解完直接画到 canvas

ws://192.168.10.123/v1/webstream/data?chn=0&streamtype=0&x-token=<JWT>

里面那层协议也翻了一遍。WS 上跑的其实还是 RTSP，WebsocketServer.js 里 binaryType 设的是 arraybuffer：控制帧是 ASCII 的 RTSP 报文（OPTIONS / DESCRIBE / SETUP / PLAY），媒体帧是二进制，前面挂 28 字节私有头，后面才是 H264

私有头以 PRAV 开头，偏移 12 的 4 字节小端是总包长，偏移 24 的 2 字节是扩展头长度，末尾还有 8 字节。想从这条连接上转推，得先剥头、再把分片重拼成整帧，折腾一圈还不如直接用官方那套播放器

逆向登录

回到登录页，F12 抓一下登录请求。password 是一串 base64，返回的 Data 是一串 JWT

密码在前端加过密，全局搜 CryptoJS，chunk-libs 里有一份，真正干活的在 app.*.js

var i = CryptoJS.enc.Utf8.parse("YJWL202101010000"),
    o = CryptoJS.enc.Utf8.parse("YJWL202101010000");

t.default = {
  encryption: function (e) {
    var t = CryptoJS.AES.encrypt(e, i, {
      iv: o,
      mode: CryptoJS.mode.CBC,
      padding: CryptoJS.pad.Pkcs7
    });
    return CryptoJS.enc.Base64.stringify(t.ciphertext)
  }
}

key 和 iv 都是写死的 YJWL202101010000，最后只取 ciphertext 再 Base64，不是默认带 Salted__ 的那种

抠出来用 Node 跑一下

const CryptoJS = require('crypto-js');

var key = CryptoJS.enc.Utf8.parse("YJWL202101010000");
var iv = CryptoJS.enc.Utf8.parse("YJWL202101010000");

var encrypted = CryptoJS.AES.encrypt("admin123", key, {
  iv: iv,
  mode: CryptoJS.mode.CBC,
  padding: CryptoJS.pad.Pkcs7
});

console.log(CryptoJS.enc.Base64.stringify(encrypted.ciphertext));
// 8VL6cdGe+KsuNwyx9Bxftg==

admin123 算出来就是 8VL6cdGe+KsuNwyx9Bxftg==

POST /v1/token/?username=admin&password=8VL6cdGe%2BKsuNwyx9Bxftg%3D%3D

这串 JWT 的 payload 解出来是这样

{
  "exp": 1795410670,
  "iss": "neuron",
  "User": "admin",
  "OrgUnit": "mycompany",
  "authorities": "ROLE_ADMIN,AUTH_WRITE,ACTUATOR"
}

顺手看了下 exp，签发到过期只有四分钟左右，大屏要一直挂着，只能自己写个定时器去刷

前端把它塞在 sessionStorage.token 里，WebsocketServer.js 建连的时候还会拿它覆盖 URL 里的 x-token，光改 query 没用

let token = window.sessionStorage.getItem("token")
if (ws.indexOf('x-token') != -1) {
  var wsUrl = ws.match(/(\S*)x-token/)[1] + 'x-token=' + token
}
websocket = new WebSocket(wsUrl);

嵌进页面

照官方抄就行：普通 HTML 放个空节点，把相机上的 h5player 按顺序引进来。容器得有明确宽高，不然 offsetWidth 是 0，建出来的 canvas 也是 0

<style>
  #videoApp { position: relative; width: 100%; aspect-ratio: 16 / 9; }
</style>

<div id="videoApp"></div>

<script>var EncodeMode = 'mf'; var TOKEN = '__TOKEN__';</script>
<script src="/static/h5player/pluginscreen.js"></script>
<script src="/static/h5player/WebsocketServer.js"></script>
<script src="/static/h5player/mfplayer/common.js"></script>
<script src="/static/h5player/mfplayer/pcm-player.js"></script>
<script src="/static/h5player/mfplayer/webgl.js"></script>
<script src="/static/h5player/mfplayer/player.js"></script>
<script src="/static/h5player/drawControl.js"></script>
<script src="/static/h5player/playerControl.js"></script>

var EncodeMode = 'mf' 这行是隐式全局，playerControl.js 里到处按它判断走哪条解码路径，不声明的话直接 ReferenceError

播放器内部会 new Worker("static/h5player/mfplayer/decoder.js")，importScripts 和 wasm 都按相对路径取，所以 Worker 必须跟页面同源

要么把页面挂到同一台设备上，要么起一层反代，把 /static/h5player 和 /v1 转过去，我们用的后者

const CAM = '192.168.10.123'

const server = http.createServer((req, res) => {
  if (req.url === '/') return res.end(fs.readFileSync('index.html'))

  const up = http.request({
    host: CAM,
    path: req.url,
    method: req.method,
    headers: Object.assign({}, req.headers, { host: CAM })
  }, (r) => {
    res.writeHead(r.statusCode, r.headers)
    r.pipe(res)
  })
  req.pipe(up)
})

server.on('upgrade', (req, socket, head) => {
  const upstream = net.connect(80, CAM, () => {
    upstream.write(
      `GET ${req.url} HTTP/1.1\r\nHost: ${CAM}\r\n` +
      `Upgrade: websocket\r\nConnection: Upgrade\r\n` +
      `Sec-WebSocket-Key: ${req.headers['sec-websocket-key']}\r\n` +
      `Sec-WebSocket-Version: 13\r\n\r\n`
    )
    upstream.pipe(socket)
    socket.pipe(upstream)
  })
})

server.listen(8099)

登录也可以丢给反代做，省得页面里再实现一遍 AES，起页面的时候把拿到的 token 替换进去就行

async function login() {
  const c = crypto.createCipheriv('aes-128-cbc', KEY, KEY)
  const pwd = Buffer.concat([c.update('admin123'), c.final()]).toString('base64')
  const r = await fetch(`http://${CAM}/v1/token/?username=admin&password=${encodeURIComponent(pwd)}`, { method: 'POST' })
  return (await r.json()).Data
}

页面这边从全局拿 token，塞进 sessionStorage，再照官方参数起播放器

sessionStorage.setItem('token', TOKEN)

var host = location.host
var proto = location.protocol === 'https:' ? 'wss://' : 'ws://'
var root = document.getElementById('videoApp')

// 两块屏、双通道并排，最后的数组是每块画布的显示宽高比
var canvasIds = createScreen(root, 2, 2, [16 / 9, 4 / 3])

var options = [0, 1].map(function (chn) {
  return {
    root: 'videoApp',
    subtype: 1,
    wsURL: proto + host + '/v1/webstream/data?chn=' + chn + '&streamtype=0&x-token=' + TOKEN,
    rtspURL: 'rtsp://192.168.10.123:9554/live?channel=' + chn + '&subtype=',
    username: 'admin',
    password: 'admin123',
    decodeMode: 'canvas',
    fullScreen: true
  }
})

options.forEach(function (opt, i) {
  var player = new Player()
  player.hide(false)
  var control = new PlayerControl(opt)
  setTimeout(function () {
    control.init(document.getElementById(canvasIds[i]), player, null)
    control.connect()
  }, 10)
})

proto 跟着 location.protocol 走，页面要是上了 https，ws:// 会被浏览器当混合内容拦掉

createScreen 第三个参数是 curCh，这里必须给 2，不然两块画布会叠在同一个位置。另外 subtype 给 1 走辅流，要 1080p 就改 0
